How small can MoE experts get before the network slows training down?

We train Mixture-of-Experts models on Clariden with the same work per token but smaller and smaller experts, spread over 1 to 8 nodes, and measure where speed drops. Then we test which optimisations recover it, for training and for serving.

The idea in three steps

01 · PREDICT

Measure the network

Time how fast GPUs exchange data inside a node (NVLink) and between nodes (Slingshot). A formula then predicts the expert size where GPUs start waiting.

02 · MEASURE

Find the cliff

Train models g1 to g16 (same work, finer experts) on 1, 2, 4, 8 nodes. Check if speed drops where the formula said.

03 · FIX

Test the tricks

Turn on one optimisation at a time (FP8, overlap, grouped GEMM…) and measure how much each recovers. Same for serving.

What it means

  1. Finer experts are slower even on one node. g16 runs at 6,100 tokens/s/GPU, g2 at 21,100. The network is fast inside a node, so this is the GPU working inefficiently: without grouped GEMM each GPU computes its experts one after another, and g16 has many tiny ones.
  2. Across nodes, finer experts lose more. From 1 to 8 nodes g4 loses 27%, g8 and g16 about 35–37%. This is the network effect the project is about.
  3. So the baseline mixes two problems. The next sweep turns on grouped GEMM everywhere to remove the first one, leaving the network effect on its own.

Words used on this page

Node
One server with 4 GPUs. Inside a node GPUs talk over fast NVLink; between nodes over slower Slingshot.
Expert
A small neural network inside each MoE layer. Experts are spread over the GPUs, so tokens travel to reach them.
g1 … g16
Our test models. gN has N times smaller experts and sends each token to N of them: same work, N times more network traffic.
Dense
A normal model without experts, for comparison.
tokens/s per GPU
The course's speed metric: how many tokens each GPU processes per second.
Baseline
A run with no optimisations turned on. Every trick is compared against it.
Grouped GEMM
Computing all of a GPU's experts in one batch instead of one by one.

Reference: all training runs

Hidden size 2048, 16 layers, sequence 4096, 15 steps on synthetic data, speed = mean of the last 5. Experts spread over all GPUs.
