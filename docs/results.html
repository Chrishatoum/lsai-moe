How small can MoE experts get before the network slows training down?

We train Mixture-of-Experts models on Clariden with the same work per token but smaller and smaller experts, spread over 1 to 8 nodes, and measure where speed drops. Then we test which optimisations recover it, for training and for serving.

The idea in three steps

01 · PREDICT

Measure the network

Time how fast GPUs exchange data inside a node (NVLink) and between nodes (Slingshot). A formula then predicts the expert size where GPUs start waiting.

02 · MEASURE

Find the cliff

Train models g1 to g16 (same work, finer experts) on 1, 2, 4, 8 nodes. Check if speed drops where the formula said.

03 · FIX

Test the tricks

Turn on one optimisation at a time (FP8, overlap, grouped GEMM…) and measure how much each recovers. Same for serving.

What it means

  1. Finer experts are slower even on one node. g16 runs at 6,100 tokens/s/GPU, g2 at 21,100. The network is fast inside a node, so this is the GPU working inefficiently: without grouped GEMM each GPU computes its experts one after another, and g16 has many tiny ones.
  2. Across nodes, finer experts lose more. From 1 to 8 nodes g4 loses 27%, g8 and g16 about 35–37%. This is the network effect the project is about.
  3. So the baseline mixes two problems. The next sweep turns on grouped GEMM everywhere to remove the first one, leaving the network effect on its own.

Spreading over 2 nodes makes the exchange 6.5× slower. It matches the hardware: about 4/7 of each GPU's outgoing traffic crosses to the other node, and 40 × 4/7 ≈ 23 GB/s, close to the 25 GB/s each GPU's network card is rated for.

The prediction

A GPU can compute and send at the same time. The network stays hidden as long as each expert has enough work to cover the time its tokens spend travelling. From the DeepSeek-V4 paper, that holds when the expert width is at least

d* = GPU speed ÷ (2 × network bandwidth)

With the GPU at 300 TFLOP/s (what the dense model reached) and the measured bandwidth:

  1. On one node almost every model is fine: NVLink is fast enough even for small experts.
  2. From 2 nodes, models with experts narrower than about 3,000–5,000 should wait on the network: g4, g8, g16, and g2 from 4 nodes. Only g1 stays safe everywhere.
  3. The network model already checks out: it estimated 44 GB/s for 2 nodes before the measurement came back at 40 GB/s.
  4. Faster GPUs make it worse. At the 120 TFLOP/s the baseline actually reached, only g8 and g16 cross the line. Every trick that speeds up the maths (grouped GEMM, FP8) moves the cliff towards bigger experts. The grouped-GEMM sweep running now tests exactly this.

Running now: the grouped-GEMM sweep

In the baseline each GPU computes its experts one after another: for g16 on one node that is 32 small jobs in a row, and the GPU sits mostly idle. Grouped GEMM computes all of a GPU's experts as one big job.

The sweep repeats the full grid with this one trick turned on. It should show three things:

  1. How much grouped GEMM helps on its own, compared with the baseline. Largest gain expected for g8 and g16.
  2. Whether only the network is left: on one node all models should now run at about the same speed, so any slowdown across nodes is the network.
  3. Whether the cliff moves towards bigger experts, as the prediction says it should when the GPU computes faster.

Words used on this page

Node
One server with 4 GPUs. Inside a node GPUs talk over fast NVLink; between nodes over slower Slingshot.
Expert
A small neural network inside each MoE layer. Experts are spread over the GPUs, so tokens travel to reach them.
g1 … g16
Our test models. gN has N times smaller experts and sends each token to N of them: same work, N times more network traffic.
Dense
A normal model without experts, for comparison.
tokens/s per GPU
The course's speed metric: how many tokens each GPU processes per second.
Baseline
A run with no optimisations turned on. Every trick is compared against it.
Grouped GEMM
Computing all of a GPU's experts in one batch instead of one by one. GEMM is the name for a matrix multiplication.
All-to-all
Every GPU sending data to every other GPU at once: how tokens reach their experts.
Bandwidth
How much data per second the network moves, in GB/s.
d* (the cliff)
The smallest expert width at which the GPU still never waits for the network.
